# 开发约定

## 技能边界

每个技能目录以 `SKILL.md` 为入口，YAML 头部包含 `name` 与 `description`；名称与目录名一致，使用小写字母、数字和连字符。尚未实现的模块不放置可被误认为成品的 `SKILL.md`。

入口文件保持简短，把较长的方法说明放入技能自身的 `references/`，并从入口链接。仅在实际需要时创建 `scripts/`、`references/`、`assets/` 或 `agents/`。工作区级辅助工具放入顶层 `scripts/`；技能运行必需的文件保留在技能内部，避免分发后失效。

## 分析接口

为每个技能明确输入阶段与数据语义，例如原始测序数据、原始计数矩阵、归一化表达矩阵或差异分析结果。记录样本标识、分组、批次、物种、基因标识及参考注释版本，不静默猜测关键设计信息。

方法要求与质量阈值在具体技能中说明，避免把某个项目的参数作为所有数据的默认标准。结果应记录工具版本、关键参数、输入来源，以及涉及随机过程时的随机种子。

## 验证与数据

测试场景应包含有效输入、缺失关键注释和不兼容输入等实际行为，并写明可观察的预期结果。仅提交可分发的小型合成或公开测试数据，同时记录其来源；大体积数据保留在 `data/`，结果保留在 `outputs/`。

环境定义和锁定文件放入 `environments/`，按实际工具选用文件格式，不预先安装分析依赖。
